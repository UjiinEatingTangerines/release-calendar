# 브라우저 로그인 연결

웹·메뉴 막대 앱 모두 설정의 **Jira 로그인 / GitHub 로그인**을 사용합니다. 기본 브라우저에서 로그인·조회 권한을 승인하고 설정 창으로 돌아오면 사이트·프로젝트·저장소를 목록에서 선택할 수 있습니다. 비밀번호나 사용자 API 토큰은 앱에 입력하지 않습니다. 기존 로그인은 **연결 대상 선택**으로 다시 선택하고, 만료된 인증은 가능한 경우 자동 갱신합니다.

## Jira Cloud: Codex와 인증 공유

1. Codex CLI를 설치하고 평소 사용하는 개인 Codex 환경으로 실행하세요. 이 기능은 Codex 0.162.1의 App Server API로 검증했습니다. 메뉴 막대 앱에서 실행 파일을 찾지 못하면 `RELEASE_CALENDAR_CODEX`에 절대 경로를 지정할 수 있습니다.
2. **Jira 로그인**을 누르면 Codex의 `atlassian` MCP로 실제 사이트 조회를 먼저 시도합니다. 이미 인증되어 있으면 브라우저를 다시 열지 않고 앱 연결을 완료합니다.
3. 인증이 없으면 Codex App Server의 `mcpServer/oauth/login`으로 브라우저 승인을 시작합니다. 승인은 Codex가 저장·갱신하므로 같은 Codex 환경에서 앱과 Codex가 함께 사용합니다. `atlassian` 설정이 없는 경우 공식 MCP v2 주소로 추가합니다. 기존 항목이 비활성화됐거나 다른 주소를 사용하면 덮어쓰지 않고 안내합니다.
4. 연결된 사이트·프로젝트를 선택합니다. 기존 프로젝트의 인증 ID는 재사용하므로 기존 연결을 다시 만들 필요가 없습니다.

앱은 Codex의 토큰 파일이나 Keychain을 열거나 복사하지 않습니다. 앱에는 비밀이 아닌 연결 ID와 연결 여부·확인 시각만 저장합니다. **로컬 로그아웃은 이 앱의 연결만 해제하며 Codex 인증은 유지합니다.** Codex까지 로그아웃하려면 사용자가 `codex mcp logout atlassian`을 별도로 실행해야 합니다. 다른 `CODEX_HOME`이나 OS 계정에서 받은 인증은 공유되지 않습니다.

조회는 임시 Codex App Server 프로세스의 일회성 메모리 스레드에서 수행합니다. 모델 실행(`turn/start`), 프롬프트 전송, 코드 실행은 사용하지 않습니다. 허용 작업은 사이트 목록, 프로젝트 목록, 버전 목록, JQL 조회 네 가지뿐입니다. 프로젝트·버전은 `executeRead`의 고정된 작업 이름으로 호출하며 임의 도구·쓰기 호출은 거부합니다. 앱 종료와 CLI 조회 완료 시 소유한 Codex 프로세스를 종료합니다. 기존 사용자 Codex 세션은 종료하지 않습니다.

이 API는 Codex의 실험적 App Server API입니다. 호환되지 않는 버전·조회 실패·인증 취소는 오류로 표시하고 마지막 정상 데이터를 유지합니다. 기존 직접 OAuth/REST 연결은 호환성을 위해 남아 있지만 새 기본 Jira 로그인은 Codex를 사용합니다. 공유된 인증 권한이 넓더라도 앱의 조회 허용 목록은 유지됩니다. [Codex App Server](https://developers.openai.com/codex/app-server/)를 참고하세요.

## GitHub.com: GitHub CLI 브라우저 인증

1. GitHub CLI(`gh`)가 설치되어 있어야 합니다. macOS에서는 `brew install gh`로 설치할 수 있습니다.
2. **GitHub 로그인**을 누릅니다. 앱에 일회용 코드와 **인증 코드 복사** 버튼이 나타나고 기본 브라우저의 GitHub 기기 인증 화면이 열립니다.
3. 코드와 로그인할 계정을 확인하고 승인합니다. Client ID·client secret·개인 토큰을 입력하지 않습니다.
4. 앱으로 돌아오면 접근 가능한 저장소를 선택할 수 있습니다. 최초 사용자 승인, 조직 정책 및 SSO 승인은 여전히 필요합니다.

공식 `gh auth login --web` 흐름을 사용하며 GitHub CLI의 클라이언트 ID를 코드에 복제하지 않습니다. 로그인은 격리된 임시 `GH_CONFIG_DIR`에서 실행합니다. 기존 `GH_TOKEN`·`GITHUB_TOKEN`, 터미널의 활성 계정, Git 자격증명 설정과 공유 키체인은 사용하거나 변경하지 않습니다. CLI의 일시적인 평문 저장은 소유자 전용 임시 디렉터리 안에서만 이루어지고 성공·실패·취소 시 삭제됩니다. 인증 토큰은 앱의 기존 0600 로컬 인증 저장소에 옮겨 이후 웹·앱·CLI가 재사용합니다. OS 강제 종료 등으로 정리가 중단되면 임시 폴더 `release-calendar-gh-*`가 남을 수 있습니다.

**GitHub CLI 승인은 `repo`, `read:org`, `gist` 등 쓰기를 포함하는 범위일 수 있습니다. 토큰 자체가 읽기 전용이라는 뜻은 아닙니다.** 앱은 저장소 목록·PR·커밋·검사에 대해 허용한 GET만 사용하고 쓰기 명령을 실행하지 않습니다. 제한된 토큰이 필요한 사용자는 고급 수동 설정을 사용할 수 있습니다. 기존 GitHub App 인증은 호환성을 위해 유지합니다.

미설치·승인 거부·실행 실패·취소·10분 만료를 상태로 표시합니다. 로그인 준비 단계는 30초 제한이며 앱 종료 시 소유한 로그인 프로세스를 중단하고 임시 디렉터리를 정리합니다. 일반 브라우저와 기존 GitHub CLI 세션은 종료하지 않습니다. [공식 CLI 로그인 안내](https://cli.github.com/manual/gh_auth_login)를 참고하세요.

## 로컬 처리와 제한

- 설정 창을 다시 열거나 새로고침해도 서버에서 진행 중인 로그인을 복구합니다. 승인을 마치지 못했다면 **로그인 취소** 후 다시 시작할 수 있습니다. 로컬 로그아웃은 같은 제공자에서 앱이 진행 중인 로그인도 취소합니다. 저장된 인증이 해당 제공자에 하나뿐이면 일반 **로그인** 버튼도 기존 인증 ID를 재사용합니다. 로그아웃한 인증은 카드에서 숨기고 로그인 버튼만 표시합니다. 로그인 완료 시 인증 시각을 갱신하며, 로그인된 제공자는 중복 로그인 버튼을 비활성화합니다.
- 기존 직접 OAuth·GitHub 액세스/갱신 토큰은 `~/.config/release-calendar/connections.json.oauth.json`에 0600으로 저장합니다. 암호화·Keychain 저장은 제공하지 않습니다. 사용자 지정 설정은 기존 관리 파일 뒤에 `.oauth.json`을 붙인 경로를 사용합니다.
- 브라우저와 앱에는 상태와 로컬 인증 식별자만 내려보냅니다. 저장된 토큰이나 client secret은 반환하지 않습니다. 앱·웹·CLI가 같은 인증 저장소를 읽습니다.
- 기존 직접 Jira 및 GitHub App 로그인에서는 `127.0.0.1:4318` 콜백 서버를 열며 완료·거부·취소·10분 만료·앱 종료 시 닫습니다. 웹 달력 서버의 포트와는 별개입니다. 다른 창/프로그램이 사용 중이면 안내 후 중단합니다.
- 외부 POST는 인증 등록·교환·갱신과 MCP 프로토콜 전송에 사용합니다. MCP 호출은 `getAccessibleAtlassianResources`, `listJiraProjects`, `getJiraProjectVersions`, `searchJiraIssuesUsingJql`로 제한합니다. 그 밖의 도구와 쓰기·삭제 호출은 전송 전에 거부합니다. 기존 REST/GitHub 조회는 GET입니다.
- 직접 OAuth·GitHub의 **로컬 로그아웃**은 앱의 로컬 토큰만 삭제합니다. Codex 연결은 앱의 연결 표시만 해제합니다. 기존 연결을 복구할 수 있도록 비밀이 아닌 로컬 인증 ID는 남깁니다. 로그아웃 후 **로그인**은 같은 ID에 새 토큰을 저장하여 기존 연결과 캐시를 유지합니다. 제공자에서 앱 승인을 철회하거나 앱을 삭제하는 작업은 각 서비스에서 직접 합니다. **연결 해제**와 OAuth 로그인 삭제는 별도입니다. 전체 로컬 인증을 제거하려면 OAuth 파일과 기존 credentials.json·환경변수도 확인하세요.
- 앱 등록 정보를 바꾸면 해당 제공자의 기존 토큰을 제거하고 다시 인증 상태로 표시합니다. 로그인 갱신은 파일 잠금 안에서 처리하여 여러 프로세스가 같은 회전형 갱신 토큰을 동시에 소비하지 않게 합니다. 갱신 실패 시 원본 캐시를 삭제하지 않습니다.
- 개인 소유·단일 사용자 로컬 운영을 대상으로 합니다. Codex 연결에는 앱의 번들 비밀키나 중계 서버가 필요하지 않습니다. 기존 3LO·GitHub App의 비밀키도 공개 저장소나 번들에 포함하지 않습니다. 외부 호스팅은 생성하지 않았습니다.
- 실제 제공자 로그인은 등록된 앱과 사용자의 승인이 있어야 확인할 수 있습니다. 가상 인증 응답을 이용한 검증과 실제 계정 인증을 구분합니다.
